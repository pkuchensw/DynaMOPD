各系统独立使用 8×H20，全局 batch 512，sampled K1，同一场景的输入一致，实际采样长度会有差异。图中给出选中步的有效回答 token。首步和末步也可回放，稳态比较只使用第 2、3 步。图页顶部标注所选场景的实测日期。

DynaMOPD 从 round_start 计时，按 executor_ready 的组到物理卡映射绘制。生成按实际副本请求数、评分按请求 seed 的 TP1 路由定位到卡；区间边界为卡组回执。合并期间源和目标均预留。换岗按回执的 unload_s 拆分，余段包含加载与等待。“三项并行”行用三色叠带标出至少各有一组生成、评分、训练的墙钟交集。

KDFlow 与 verl 以各步最外层 rollout 调用起点对齐，步长来自框架计时。请求条合并同卡、同类且时间相交的调用。KDFlow 每行合用两个标识。生成阶段按客户端进入 generate_one 的顺序轮询重建副本 A–H，使用请求实测起止时间。蓝色表示推理，沙色表示等待。其他阶段按物理 GPU 0–7 的实测记录绘制。网络可能改变请求到达 router 的顺序；A–H 与物理卡号的对应关系未知。贯穿八行的色带表示教师卡池的整体换岗调用。悬停显示该时刻全池实测在途数；若剩 N 个请求，最多 min(N,8) 张 TP1 卡能同时处理它们。verl 的单卡请求按 worker 的可见 GPU 和运行模式区分学生与冻结教师。训练、重算和发布按 worker 的外层调用绘制，嵌套状态搬移可与其重叠。图中没有 kernel 利用率采样。

一轮训练的调用链

launch.sh → run.main → trainer.fit → Controller.run_round。Driver 读入配置和数据，创建算法、策略和执行器。Controller 是轨迹与卡组状态的单一写入者。策略提出动作，controller 领取租约，worker 在安全点执行。Controller 收到完成回执后更新状态，开始下一次决策。

  1. 全卡生成SGLang 返回确认的 token、行为 logprob 和停止原因。
  2. 按路由评分Controller 收集同一教师的前缀，组批发送，按轨迹及区间接回监督。
  3. 就绪微批反向终止并收齐监督的样本交给空闲训练组，其他组继续服务本轮。
  4. 全批更新与屏障归约梯度，执行一次 AdamW，发布新权重。所有 rollout 组确认后进入下一轮。

数据与算法层

一条轨迹保存三种进度

数据入口将 JSONL 或 Parquet 中的 prompt 按 student 模板分词，检查教师与学生的 token ID 含义。每题在入队时取得 v{version}/r{index}、请求 seed、生成上限和一条教师路由。多个教师各自服务一部分轨迹，同一轨迹目前使用一位冻结教师。

Row.tokens、behavior
学生已经确认的回答和逐 token 行为 logprob。owner 指定可以继续采样的卡组，迁移后 ID 与已发布前缀保持连续。
Row.labels
教师已交付的连续监督，区间按回答位置记为 [start, end)。同一轨迹同时至多有一个在途评分区间。
Row.kv
记录哪个教师卡组可能续算到哪个位置。命中量以引擎回执的 cached_tokens 为准。驱逐 KV 后保留已交付监督，下段可从真实前缀重算。

例如已有 256 个回答 token 完成评分，下一段从回答位置 256 开始。Worker 将 prompt 和回答送到该段末尾，设置 logprob_start_len = len(prompt) + 256 − 1。SGLang 返回的首项是前驱 ID 和空 logprob。Worker 核对前驱及目标 ID 后取后续各项，所以 chunk 的第一个新 token 也有对齐的教师分数。

建样本与路由Row.prefix / deliver / readyInference.score整段、续评与清缓存重算校验

比较系统时采用同一份 sampled K1 配方

当前 DAPO 对照保留 EOS 和达到长度上限的真实回答 token，终止且监督齐备才进入训练。FSDP2 在轮初权重上先无梯度重算 old logprob，再做可求导的 actor 前向。对采样位置取 advantage = (teacher_logp − current_logp).detach()，使用 verl 的 vanilla PPO 裁剪及 dual clip。直接调用原生 verl 的同输入回归覆盖 EOS、截断、padding 和裁剪分支，逐元素梯度及一次 AdamW 后参数的最大绝对差均为零。独立 on-policy 运行仍可能采到不同的回答。

扩展算法可实现 DistillationAlgorithm.route 和 token_loss(TokenBatch)，声明所需监督。仓库另提供 sampled reverse KL、重要性加权的 sampled forward KL、教师 top-k 交叉熵。Driver 在申请 GPU 前检查执行器能否提供对应监督。

执行层与资源交接

自然转岗和请求合并

8×H20 配置把 GPU 划为四个双卡组。轮初每张卡上各有一个 TP1 student 副本，同一组的两张卡也可以组成 FSDP2 分片组。自然排空的组可以立即申请下一份工作。主动合并则经过 hold → export → install → release，源和目标都要到达解码块边界。源交出已确认前缀、seed 和绝对位置，目标检查各副本的可用 KV 容量、为下次 decode 留出空间，再以零生成 prefill 恢复前缀。只有目标接受后源才释放所有权。容量拒绝会保留原归属，并进入调度记录。

双组交接协议export / install / release副本路由及 KV 容量

切换冻结教师

相同推理配置的模型可复用 SGLang 进程，每次接卡仍要加载该角色的权重。Qwen2 的兼容判断考虑上下文和位置编码，支持的配置可显式恢复 RoPE。架构不兼容时走独立教师 rank 的租约路径。14B 配置在 CPU 上预先导入依赖，到首次 CUDA 操作前等待。接卡后才加载 14B 参数并建立 KV 池，释放时回收 GPU 子进程，逐卡用 NVML 核对相关 PID 已退出。持有教师租约的仍是本轮共享卡组。

接卡时检查保留 trainer 状态后的可用显存及教师实际 KV 容量。14B 配置还会把带版本的 FP32 参数和 AdamW 状态提前镜像到主机，下一次迁出可复用同版本副本。真实训练中五次进入 14B 的总交接为 6.42–7.62 秒，退出为 0.25–0.37 秒。释放后立即重申请的独立压力实验用了 24.36 秒，其中 18.91 秒花在等待 CPU 准备。

借卡执行宽 TP

当前真机配置预建 GPU 0–3 和 4–7 两个 SGLang TP4 引擎，保留通信组与已捕获的解码图。休眠时权重备份在 CPU，释放受内存管理器控制的 GPU 缓冲区。两组在开训前并行准备约 74.5 秒，每卡待命仍占约 2.0–2.65 GiB。调度器在单条尾请求的块边界为两个组取得独占租约，worker 复查显存和 student 版本。目标重算前缀，核对最后一个 token 的 ID 和行为 logprob，再按原 seed 与绝对位置继续采样。借出训练组可以保留尚未提交的梯度；EOS 或下游服务压力达到缩回条件后归还。

宽 TP 方案采用 PAT 的预计收益判定、Flying Serving 的预建通信组，并参考 ReMP 对请求状态与执行拓扑的拆分。在线训练对推迟教师评分和微批训练的时间另行计价。PAT · Flying Serving · ReMP

训练与权重发布

先反向，后统一更新

就绪微批只归一个训练组。FSDP2 按长度均衡组内各 rank，DAPO 路径用变长 FlashAttention 2 打包独立因果序列，只对需要预测回答的位置计算 logits。每个 rank 累加本地有效 token 的损失和梯度，空 rank 也参加必要的集合通信。轮末，各组的相同分片 rank 经 NCCL 把 FP32 梯度汇到优化器组，按整轮有效回答 token 总数归一，裁剪一次、执行一次 AdamW，再同步各副本的 FP32 主参数。

发布屏障与恢复点

更新后从主参数捕获 BF16 分片，逐桶聚合并分发。SGLang 在本卡通过 CUDA IPC 消费参数，最后一个桶刷新缓存并声明新版本。有下一轮时，配对的宽引擎也消费这次发布，每个接收进程独立导出 IPC 引用。全部接收方回执后回收源缓冲。显存预算包含窄引擎唤醒、发布临时缓冲、宽引擎权重和余量，据此决定 Adam 能否留在 GPU。控制器收到所有 rollout 组的新版本确认后才开启下一轮。

持久化频率由 checkpoint_interval 控制。普通轮走内存张量发布，指定轮可保存 HF 模型和含优化器的 DCP；含训练状态的已提交版本支持恢复。此次 16K 对照末步只导出 HF 供评估。Trace 分别记录 commit、hf_checkpoint、durable 和 rollout_barrier，可据此拆出持久化耗时。

模拟与成本校准

同一份策略通过 Executor.submit(Action) 下发动作，以 wait() 收取开始、结束、剩余显存和结果。真实执行器等待引擎回执。SimRL 适配器按预测耗时将完成事件加入最小堆，将虚拟时钟推进到下一次完成。解码使用 SimRL 的 roofline 成本和逐副本 KV 块分配器，评分、训练、角色释放和权重发布各有成本项。回放从 samples-vN.jsonl 固定每题实际长度，供执行器推进 EOS；策略仍只看到已经发布的 token。

校准按服务方向、引擎生命周期、trainer 驻留及优化器位置区分换岗，按最慢训练 rank 的工作量估计打包微批。一次跨组发布在最慢组准备好后结算共享通信，较早到达的组单列等待。TP 有两种模型：一份计算 KV head 重分片、搬运字节和通信组代价；另一份使用真机宽引擎的唤醒、前缀重算、单请求解码和归还成本，同时计入待命及唤醒显存。

用新 14B 路径前两轮拟合、第三轮留出，12 次服务换岗的平均绝对误差从按角色对估计的 0.91 秒降到 0.54 秒。另一组同 token 回放中，成本搜索相对自然排空在旧 14B 流程得到 1.31×，在 7B 对照为 0.95×。这些是虚拟轮时，预测误差仍会改变合并或等待的选择。

教师放置与 K1 对齐曾比较每组预热教师副本、共享引擎、单引擎重启。随后把冻结教师放进动态卡组，并将最初只训练自然 EOS 的配置扩展为按完整 response mask 训练。对齐 old-logprob 单独前向、PPO 裁剪以及 KDFlow 的 K1 适配器。
大 batch 与多组训练DAPO batch 512 的早期实现中，最后一条回答结束后平均还需 139.58 秒训练和发布。改用八个 TP1 rollout、双卡 FSDP2 分片、多组就绪微批、同 rank 梯度归约，并优化冻结教师分桶装载。后续同布局的阶段屏障消融中，第 2–5 步平均从 103.50 降至 83.20 秒。
五场景与调度成本在 DAPO 对照、14B 教师、16K 上限、GSM8K、Math 学生上保留真实回答长度。统一核对推理 TP、训练分片、token 预算与题集。Math 学生实验修正相同词表及输出头下未命名 ID 的处理。用历史回执校准换岗和训练成本，加入预设空间搜索与虚拟等待。
14B 教师按需接卡跨架构重启曾让单次交接耗时 49–69 秒。将 CPU 准备移出接卡路径，标定实际 KV 容量，迭代对比临时迁出、仅镜像 Adam、同时镜像参数与 Adam。最终四步作业中，五次切入 14B 的交接中位数为 6.66 秒。
从热 KV 实验到宽 TP独立测试 KV 分片转移、双引擎热交接和冷重启，用 SimRL 比较维持 TP 与扩容。16K 复测采用 2,048 行分块计算输入 logprob，解决长前缀评分的显存峰值。正式训练选择预建宽引擎、取得租约后重算前缀。
宽引擎连续发布首次训练在第二次发布时显存不足，增加了宽引擎唤醒预算。复测发现两个消费进程共用一个 IPC 引用会导致缓冲回收异常。改为同一张量分别导出引用、等待双方回执并回收。最终四步更新到 v4，三次中间发布后优化器均驻留 GPU。
